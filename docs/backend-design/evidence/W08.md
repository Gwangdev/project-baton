실패 테스트가 잡은 구체적 반례: 테스트를 먼저 작성해 구현 전에는 컴파일 단계에서 실패했다. 구현 뒤 변형 검사로 다음을 확인했다. 청크 사이 권한 재확인을 제거하면 철회 뒤에도 delta가 계속 나가 QaPrivacyIT가 실패했고, 분당 한도를 제거하면 7번째 질문이 접수되어 QaStreamingIT가 실패했다. 개인 폴더 출처명 마스킹을 제거하면 파일명이 인용에 노출되어 실패했다. 그 밖의 반례: 근거 0건은 모델 호출 없이 NO_EVIDENCE(delta 없음, 확인 대상 전임자·PM)이고, 공급자 장애는 MODEL_UNAVAILABLE, 시간 초과는 MODEL_TIMEOUT, 후보 밖 인용(E99)과 인용 없는 본문은 CITATION_INVALID이며 인용 0건으로 게시되지 않는다. SSE는 meta → evidence → delta×N → done 순서이고 실패는 error로 끝난다. 같은 key 재전송은 JSON 201 동일 본문, SSE done 하나이고, 다른 본문은 409, 진행 중은 409 REQUEST_IN_PROGRESS·Retry-After 1이다. 406(application/xml)·400(2,001자, 공백, 추가 필드)은 key를 소비하지 않는다. PM·전임자·일반 구성원은 403, 비구성원은 404이고, 이력에는 다른 사용자의 메시지가 나오지 않는다. cursor 페이지와 cursor+offset 400을 확인했다. 접수 직후 프로세스가 죽은 질문은 lease·deadline 만료 뒤 recovery가 DEADLINE_EXCEEDED로 한 번만 닫고 idempotency를 완료하며, 살아 있는 lease는 건드리지 않는다. 그 뒤 늦게 도착한 답변은 게시되지 않는다(답변 1건 유지). 클라이언트가 끊기면 CLIENT_DISCONNECTED로 한 번만 닫힌다. 미해결 충돌은 두 기록을 근거와 프롬프트(UNRESOLVED CONFLICT)에 함께 올리고, stub은 두 기록을 모두 제시한다.

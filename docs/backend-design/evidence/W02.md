실패 테스트가 잡은 구체적 반례:
- Spring Session 기본 쿠키명이 `SESSION`이어서 `BATON_SESSION`으로 보호 요청을 재현할 수 없었다. `DefaultCookieSerializer`를 계약의 HttpOnly/SameSite=Lax/Path=/ 속성으로 설정해 JDBC 세션을 재사용하도록 고쳤다.
- Spring Boot 4의 일반 test starter에는 MockMvc 자동설정이 없어 MVC test starter를 추가했고, SecurityContext JDBC 직렬화에서 CurrentActor가 Serializable이 아니었던 오류를 수정했다.
- CSRF 예외는 일반 AccessDeniedException보다 상위 타입으로 처리해야 `CSRF_REQUIRED`가 된다. 비밀번호 오류·입력 검증·Security filter의 오류도 공통 Problem body로 통일했다.
- 같은 idempotency key의 최초 응답과 PostgreSQL jsonb 재생 응답은 공백 표현이 달랐다. 요청과 응답 모두 canonical JSON으로 해시/반환해 동시 재생 결과를 일치시켰다.

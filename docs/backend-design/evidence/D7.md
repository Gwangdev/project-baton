## 구현하며 바꾼 것
- **migration을 앱 밖으로.** 처음에는 앱이 소유자 계정의 별도 연결로 migration하게 했으나, (1) 앱의 DataSource가 연결 풀 셋을 라우팅하는 구성이라 Spring Boot가 Flyway용 연결을 파생하지 못했고, (2) 그렇게 하면 앱 컨테이너가 소유자 비밀번호를 늘 들고 있어 앱을 장악한 쪽이 트리거를 끌 수 있었다. 같은 앱 이미지의 다른 진입점(`DatabaseMigration`)을 일회용 컨테이너로 돌리고, 소유자 비밀번호는 db·migrate·backup만 받는다.
- **기준 덤프의 운반.** SSH를 열지 않으므로 파일을 올리지 않고, CI가 덤프를 만들어 작은 이미지에 담아 ECR에 올린다(데모 비밀번호는 GitHub 비밀값). 호스트의 `deploy.sh`가 꺼내 두고, 빈 DB면 한 번 불러온다.
- **격리 검증 보정(2026-10-21, 대장 214~225).** 전송 할당을 넘은 동안에는 매 실행 프록시를 멈춘다(재배포가 다시 띄워도 5분 안에, `deploy.sh`는 띄운 직후 바로 멈춘다). `egress-quota-check` 9건. CI는 이미지 셋을 모두 만든 뒤 올리고 `deploy.sh`는 기준 덤프를 먼저 받는다. 없는 `/assets/*`는 404이고 immutable이 붙지 않는다(`deploy-overlay-check` 15건째). db 상태 확인은 TCP로 한다. 로그인 안내와 README가 접속 주소 기록과 매일 삭제를 알린다. 공개 데모는 백업하지 않는다(매일 기준 덤프로 되돌리므로; 사용자 결정): overlay·CI·ECR에서 backup을 뺐다. 실행 로그: `~/baton-results/d7-evidence/2026-10-21-verification/`(검증 때 전 시험)과 `2026-10-21-corrections/`(보정 뒤 바뀐 부분), 각 폴더의 `summary.txt`·`memory.log`.
- **연결 한도의 훅.** Docker가 공개한 포트로 오는 패킷은 input이 아니라 forward 훅을 지나므로 규칙을 forward에 건다.

실패 테스트가 잡은 구체적 반례: HTTP·SSE·폴링·세션 테스트를 먼저 작성했고, 구현 전에는 모듈이 없어 실패했다. 구현 뒤 테스트가 잡은 결함과 조치는 다음과 같다. (1) 확인 대기함의 「더 보기」가 현재 페이지가 비면 사라져, 「내 연결분」처럼 걸러 보는 뷰에서 다음 페이지로 갈 수 없었다 — 버튼을 표 밖으로 옮겼다. (2) 실제 백엔드 E2E에서 로그아웃 직전 CSRF 토큰 요청이 네트워크 단계에서 끊기자 재시도 없이 실패했고, 세션 store는 서버 세션이 살아 있는데도 화면 상태만 지워 로그아웃된 것처럼 보였다 — CSRF 토큰 요청도 같은 네트워크 재시도에 넣었고, 서버가 로그아웃에 성공했을 때만 화면 세션을 끝내며 실패는 셸에 오류로 보인다. (3) Vite dev 서버의 의존성 재최적화가 테스트 도중 페이지를 새로 고쳤다 — 실제 백엔드 E2E는 운영용 api 빌드를 vite preview로 띄운다. (4) E2E teardown이 Gradle 프로세스 그룹만 멈춰 JavaExec가 띄운 백엔드 JVM이 남을 수 있었다 — API 포트를 연 PID도 멈춘다. 그 밖의 단언: 2^53 이상 ID·숫자 code·음수 version은 ContractViolation, 경로의 'REC-103'은 요청 전에 거부, CSRF 403은 한 번만 재취득 후 같은 키 재전송, 409 REQUEST_IN_PROGRESS는 Retry-After 뒤 같은 키, 412/428/409/429/503은 재시도 없이 code·traceId·Retry-After를 화면에 넘김, SSE 순서 위반은 표시하지 않음, done 없이 닫힌 스트림은 중단, 폴링은 조회만 하고 한도가 지나면 멈춤.

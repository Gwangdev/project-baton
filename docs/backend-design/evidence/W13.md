## 설계에 없던 발견과 조치
- **Google의 임베딩은 별도 starter다.** 채팅 starter에는 임베딩 클래스가 없다. 또 임베딩 연결 구성은 속성과 무관하게 항상 만들어지고 키(또는 Vertex 프로젝트)가 없으면 실패한다. 다른 공급자만 쓰는 배포가 시작되도록 자리표시자 키를 두었고(비밀이 아니다), Google을 고르고 키를 빠뜨리면 `AiSettings`가 막는다.
- **임베딩 어댑터가 기동할 때 공급자를 호출했다**(차원을 묻는 검사). 키나 네트워크가 없으면 서비스가 시작되지 않았다. 호출을 없애고 벡터를 돌려받을 때 검사한다.
- **소형 로컬 모델은 JSON을 요구해도 평문으로 추론한다.** 공급자의 JSON 모드로 해결했다(`evidence/model-profile.md` 「발견」).
- **새 의존성이 Jackson 2의 권고 7건을 끌어왔다.** SDK가 쓰는 2.21.5를 BOM으로 2.21.7로 올렸다.
- **코드 리뷰(수동)에서 찾은 것:** `EmbeddingBackfill`이 처음에는 주기마다 `work_records` 전체를 훑는 질의였다(큰 데이터에서 1분마다 전체 스캔). id 창 단위로 순회하게 고쳤다.

## 보안 점검(/security-review는 origin/HEAD가 없어 실행되지 않았다. 수동)
- **외부 전송:** OpenAI·Google은 `BATON_AI_EXTERNAL_TRANSMISSION=approved` 없이는 시작하지 않는다. 평가 도구는 합성 표식이 있는 집합만 보낸다. 이 작업에서 외부 공급자 호출은 하지 않았다(키가 없고, Ollama는 로컬이다).
- **비밀:** 키는 환경변수로만 읽고, 기동 로그·오류 메시지·저장소에 값이 없다(시험으로 로그 전체 검사). compose는 값이 아니라 변수 이름만 넘긴다.
- **프롬프트 주입:** 평가에 근거 안의 지시문 5문항이 있고 소형 모델도 5/5를 통과했다. 방어(경계 태그, 인용 서버 재구성, 엄격한 파서)는 바꾸지 않았다.
- **새 의존성:** OSV 269좌표(런타임 223, 테스트 전용 46) 0건(Jackson 2 상향 뒤). 외부로 나간 것은 공개 라이브러리 이름과 버전뿐이다.
- **판정:** 새 취약점을 찾지 못했다.

## 보정(2026-10-13, 대장 156)
- 위 「Google의 임베딩은 별도 starter다」의 자리표시자 키는 Compose에서 동작하지 않았다. Compose는 설정하지 않은 `GOOGLE_API_KEY`를 빈 문자열로 넘기고 Spring은 빈 값을 설정된 값으로 본다. 그래서 2026-10-05 이후 키 없는 Compose 스택(stub 포함)은 기동하지 못했다. 최종 코드 부하 재측정의 첫 시도에서 드러났다.
- 고친 방식: Google 임베딩 연결 자동 구성을 `spring.autoconfigure.exclude`로 빼고, `config/GoogleEmbeddingConnectionConfiguration`이 Google 텍스트 임베딩 모델과 같은 스위치(`spring.ai.model.embedding.text=google-genai`)일 때만 그 구성을 불러온다. 자리표시자 키는 없앴다. Google을 고르고 키를 빠뜨리면 여전히 `AiSettings`가 변수 이름을 말하며 막는다.
- 시험: `AiProviderIT`의 기본값을 Compose와 같은 빈 문자열로 바꾸고 빈 키 시나리오를 더했다. 구현 전 5건 실패, 구현 뒤 10/10. `@Import`를 빼는 변이에서 Google 시나리오 2건이 실패한다. 배포 형태 확인 `tests/deploy/compose-start-check.sh`는 구현 전 실패, 구현 뒤 통과했다.

## 체크포인트 리뷰

- `/code-review`(high) 1회, 7건 보고: 고침 3(관리자 행의 발급 버튼과 데모 저장소가 서버 규칙과 어긋남, 복구 플래그만 있으면 조용히 무시됨, 시험 주석의 대장 번호), 안 고침 4(복구 비밀번호 길이, 로그인 경로의 감사 실패 결합, 비동기 스레드의 추적 ID, 관리자 주소 노출 — 대장 125~128에 사유).
- `/security-review`는 origin/HEAD가 없어 실행되지 않았다. 수동 점검: ① 관리자가 다른 관리자를 탈취하는 경로(설정 코드)가 막혔다. 일반 계정은 여전히 코드를 가진 관리자가 탈취할 수 있으나 로그인·발급·설정이 주소와 함께 남고 본인이 볼 수 있다(A-11). ② 복구는 배포 변수를 바꿀 수 있는 사람만 쓰고 세션을 끊으며 감사가 남는다. 켜진 채 기동마다 경고한다. ③ `accountActivity`는 본인의 행만 읽는다(쿼리의 actor·target이 본인). ④ 추적 ID는 서버가 만들고 클라이언트 값을 쓰지 않는다. ⑤ 로그인 실패는 감사하지 않아 인증 전 경로가 감사 표를 채울 수 없다. ⑥ 새 비밀·키 값은 어디에도 쓰이지 않았다. 새 취약점을 찾지 못했다.

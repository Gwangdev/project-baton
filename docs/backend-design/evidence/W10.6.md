(2) V12 인덱스(P3): SchemaIT.ordersTheTimelineAndTheLatestJobPerTargetFromIndexes가 V12 없이 실패하고 추가 뒤 통과한다.
(3) 검색 트랜잭션(P4): EvidenceRetrievalIT.theQuestionIsEmbeddedBeforeAnyDatabaseTransactionOpens가 「expected [false] but was [true]」로 실패했다. retrieve()의 @Transactional(readOnly)을 없애 임베딩을 트랜잭션 밖에서 계산한다.
(4) pool 분리(P4): FailureIsolationIT.generalApiKeepsItsConnectionsWhileWorkerQueriesHoldAllTheyCanGet이 pool 하나일 때는 테스트 쪽 쿼리조차 연결을 얻지 못해 실패했다(worker 경로가 20개를 모두 가져감). 분리 뒤 worker 경로는 8개 이하에서 멈추고, 일반 API 450건 오류 0, p95 12.4~15.9ms다.
    readiness 결함도 이 테스트가 잡았다. Spring Boot의 db 지표는 라우팅 DataSource 뒤의 pool을 모두 검사해서, worker pool이 고갈되면 서비스 전체가 readiness 503이 됐다. dbHealthIndicator bean을 두어 API pool만 검사하게 했다.
(5) claim과 sweep 분리(P5): JobRecoveryIT.claimLeavesExpiredLeasesAndUsedUpAttemptsToTheSweep이 실패했다(claim이 만료 lease를 회수해 바로 가져감). 시도 3회 제한은 claim의 선택 조건(attempts<3)으로 옮겨, sweep 전에도 넘지 않는다.
(6) 보존(P5): RetentionIT 3건이 빈 run()에서 단언으로 실패했다. 구현 뒤 기간이 지난 성공·실패 job만 지우고, 미종료 job은 남긴다. 스위치가 꺼지면 job은 0건 삭제한다. 만료된 COMPLETED 멱등 행은 지우고 IN_PROGRESS 행은 남긴다. 12,001행을 5,000행씩 끝까지 지운다.
(7) 종료 대기(P6): JobSlotsTest.shutdownLetsARunningJobFinishAndStartsNoOther가 「shutdown returned while a job was still running」으로 실패했다. drain 25초를 둔 뒤 통과한다. drain을 넘은 job을 인터럽트하는 사례는 변경 전에도 통과했으며 상한 회귀 기준으로 둔다.
